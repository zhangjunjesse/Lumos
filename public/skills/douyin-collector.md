# 抖音采集器 / Douyin Collector

当用户要采集、整理、总结抖音公开内容，或者按博主 / 关键词批量收集时，优先使用 `douyin-collector` MCP。不要自己写脚本抓抖音页面，也不要绕过抖音采集器直接操作数据库。

## 一条铁律:不要按内容类型选工具

抖音的视频(`/video/`)和图文(`/note/`)用**同一套工具**。你不需要先判断用户给的是哪一种 —— 直接把链接、短链、完整分享文案或 aweme_id 丢给 `douyin_collect`，它自己展短链、认类型、走对应的处理链路。

视频取字幕/ASR，图文取正文和图片上的文字，之后总结和入库的流程完全一样。

不支持的类型(直播等)会返回明确的 `type` 和 `reason`。**收到这种结果就如实告诉用户，不要换别的工具重试** —— 换哪个都一样不支持。

## 决策规则

- 单条作品采集 + 默认处理:用 `douyin_collect`。视频图文通用，默认会采集、取文本、总结，并写入默认知识库。
- 已采集的只要总结:用 `douyin_summarize`。默认不入库；用户明确要求入库时设置 `publish_to_knowledge=true`。
- 已采集的要完整处理:用 `douyin_process`。默认会取文本、总结，并写入默认知识库。
- 只想知道这条链接是什么、或只要元数据:用 `douyin_get_detail`。它会返回内容类型。
- 只取文本不总结:用 `douyin_get_transcript`。
- 列出已采集的内容:用 `douyin_list_content`。
- 按关键词采集:用 `douyin_search_keyword`。它会创建或复用关键词订阅并立即执行一次采集，默认会继续取文本、总结并入库；只要元数据时设置 `auto_process=false`。
- 按单个博主采集:用 `douyin_collect_creator`。
- 批量博主 / 关键词 / 链接采集:用 `douyin_batch_collect`。默认只采集元数据，避免大批量 ASR 产生费用；用户明确要求"总结 / 入库 / 处理这批"时设置 `auto_process=true`。

## 重要边界

- `skill` 只负责告诉 AI 怎么选工具；真正执行必须走 MCP。
- 不要声称已绕过抖音风控、验证码或登录限制。
- 不要在工具失败时编造标题、文本、总结、销量或采集结果。
- 只拿到标题、作者、封面、链接、描述、metadata-only 结果时，不能推断或模拟作品里的内容;这些信息不是文本证据。图文只拿到正文没读出图片文字时同理 —— 图文的内容常常主要在图里。
- 取文本 / 总结 / 入库失败或为空时，必须把 `phase` / `error` / `reason` 原样解释给用户，并说明去 `应用 > 抖音采集器` 里更新 Cookie、重试、强制 ASR 或手动入库，不得补写"可能的字幕"。
- 不要用 Bash / Python / 浏览器脚本直接抓抖音来替代 MCP；错误要回传给用户。

## 成本和批量策略

批量处理可能触发大量 ASR / 总结 / 入库调用。除非用户明确说要"总结这批""入库这批""处理这批"，否则 `douyin_batch_collect` 保持默认 `auto_process=false`。

图文另有一笔成本:图片上的文字优先用本地 OCR 读(不花钱)，识别质量不达标时会自动改用视觉模型(按图计费)。工具结果里会写明各有几张走了哪条路，转述时如实说。

如果用户明确要求总结或入库：

```json
{
  "tool": "douyin_batch_collect",
  "arguments": {
    "creators": ["<sec_uid 或主页链接>"],
    "keywords": ["AI 赚钱"],
    "auto_process": true,
    "publish_to_knowledge": true
  }
}
```

## 错误处理

- 返回 `Cookie` / `登录` / `风控` / `验证` 相关错误：告诉用户去 `应用 > 抖音采集器 > 设置` 更新 Cookie 或完成登录状态检查。
- 返回 `未找到默认知识库 collection`：告诉用户先在抖音采集器设置默认知识库，或本次把 `publish_to_knowledge=false`。
- 返回 `reason: unsupported-content-type`:如实说明这类内容(如直播)采集器不支持，不要换工具重试。
- 返回 `reason: short-link-unresolved`:短链没展开，让用户在浏览器打开短链后把跳转到的完整链接粘过来。
- 批量结果里有 `failures`：明确说明哪些目标失败、哪些成功，不要只说"已完成"。
- 返回 `ok:false`：按原始 `phase` 和 `error` 解释，不要包装成成功。

## 回复口径

成功时说明采集了多少条、分别是视频还是图文、是否已总结、是否已入库。部分成功时必须写清失败数量和失败原因。工具不可用时直接说"抖音采集器 MCP 未就绪"，不要换成自制采集方案。
