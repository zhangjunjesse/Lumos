# Etsy 选品阶段 SOP 分析

全量导出：`docs/etsy-ops-handbook-everstream-export.md`

## 结论

这份手册里的选品流程不是“输入关键词 -> 抓几个商品 -> AI 生成候选”。

它更接近一个标准化商品立项流程：

1. 市场趋势调研
2. 竞品初筛
3. 用户需求提取
4. 产品定义
5. 利润测算
6. 选品决策
7. A/B/C 评级
8. 进入上新准备

所以当前电商应用的“选品研究”体验差，根本原因是产品形态缺少事务化研究过程、原始样本池、用户需求拆解、利润测算和决策解释。现在的界面像是直接展示 AI 的结论卡，而不是展示一个运营人员能审核、复盘、接着执行的 SOP。

## 手册里的选品标准

选品目标要求产品同时满足五类条件：

| 标准 | 含义 | 对产品 UI 的要求 |
| --- | --- | --- |
| 有明确搜索需求 | 需要用产品词和关键词验证需求，不只是模型觉得有需求 | 必须展示关键词、搜索来源、搜索结果数量或样品证据 |
| 有成交但竞争适中 | Etsy 上已有成交记录，但 review 数不要过高 | 必须展示竞品 review、价格区间、是否头部垄断 |
| 有品牌空间 | 能做视觉、命名、包装、场景差异化 | 必须展示“竞品长什么样”和“我们准备怎么不一样” |
| 利润空间 >= 30% | 不能只看售价，要看成本、平台费、广告、包装、物流 | 必须有利润测算，不应只给“利润分” |
| 可复购或节日热销 | 要么有持续购买场景，要么有节日/礼品周期 | 必须标记适用节日、送礼场景、复购可能性 |

这意味着选品结论不能只是一张推荐卡。用户必须先看到“这个判断是怎么来的”。

## 标准选品 SOP

### 1. 建立研究任务

每次研究必须是一个独立任务，而不是把候选混入全局列表。

任务字段应包含：

| 字段 | 示例 |
| --- | --- |
| 研究主题 | 戒指 / personalized ring / wedding gift |
| 目标市场 | 美国 / 英国 / 德国 / 日本 |
| 平台 | Etsy / Amazon / Pinterest / Instagram / TikTok / 1688 |
| 价格带 | $20-40 |
| 研究策略 | 蓝海 / 跟款 / 节日 / 常青 |
| 任务状态 | 抓取中 / 分析中 / 待确认 / 已完成 / 失败 |
| 产物数量 | 样品数、详情页数、候选数 |

用户应该能回看一次研究的完整过程。

### 2. 市场趋势调研

手册要求通过 EtsyHunt、eRank 等工具分析关键词热度，锁定品类机会。

在应用里应该转换成：

| 输出 | 用户要看懂什么 |
| --- | --- |
| 关键词池 | 本次到底研究了哪些关键词 |
| 平台搜索 URL | 去哪里搜的 |
| 热度判断 | 需求强 / 中 / 弱 |
| 季节属性 | 是否节日驱动 |
| 长尾词机会 | 是否存在更窄的切入词 |

当前应用只展示“关键词：戒指”，这不够。用户不知道 AI 后续候选是不是围绕正确关键词展开。

### 3. 竞品初筛

手册要求查看 Top100 同类商品的价格区间、review 数量、图文风格。

应用里至少要先展示一个“原始竞品样本池”：

| 必须字段 | 说明 |
| --- | --- |
| 商品图 | 没图就不直观，用户无法判断视觉风格 |
| 原始标题 | 保留平台原标题 |
| 平台 | Amazon / Etsy / Walmart 等 |
| 价格 | 用于判断价格带 |
| 评分 / review | 用于判断竞争和需求 |
| 商品链接 | 用户可点开核实 |
| 抓取状态 | 搜索页样品 / 详情页已打开 / 详情失败 |
| 样品标签 | 头部品牌、低价款、礼品款、可定制款、同质化款等 |

这一步是当前体验最大缺口。没有原始商品标题、图、关键词和链接，用户无法信任后面的 AI 结论。

### 4. 用户需求提取

手册明确要求阅读买家评价，提取真实使用场景与痛点关键词。

即使第一版不能抓评论，也应该有一个明确状态：

| 状态 | UI 表达 |
| --- | --- |
| 已抓评论 | 展示正/负面评价摘要、痛点词 |
| 未抓评论 | 明确显示“本次未读取买家评论，痛点来自商品标题/详情推断” |
| 被拦截 | 展示失败原因和可重试动作 |

用户需求输出应该拆成：

- 买家想要什么
- 买家担心什么
- 现有竞品没有解决什么
- 哪些词反复出现
- 哪些场景适合做 Listing 文案

当前“差异化”是一整段 AI 文本，用户很难判断它到底来自哪里。

### 5. 产品定义

手册要求确定核心卖点、材料规格、预估定价。

候选卡应从“AI 分析卡”变成“产品立项卡”：

| 模块 | 内容 |
| --- | --- |
| 产品名 | 中文可读名称 + 英文 Listing 方向 |
| 目标人群 | 给谁买、谁使用 |
| 使用场景 | 结婚、纪念日、母亲节、日常佩戴等 |
| 对标竞品 | 具体引用哪几个原始商品 |
| 规格建议 | 材质、尺寸、颜色、包装、定制项 |
| 视觉方向 | 主图风格、模特/场景/包装图需求 |
| 标题关键词 | 初步英文关键词组合 |

这比“Titanium Hypoallergenic Minimalist Ring with Comfort Fit”这种英文标题更适合普通用户做判断。

### 6. 利润测算

手册要求计算材料、人工、平台费、广告预算、包装、物流。

应用不能只显示“利润 68”。应该展示可编辑测算：

| 项目 | 示例 |
| --- | --- |
| 预估售价 | $24 |
| 采购/制作成本 | 用户可填或从 1688/Alibaba 估算 |
| 包装成本 | 礼盒、卡片、耗材 |
| 物流成本 | 国内/国际/平台配送 |
| 平台费 | Etsy/Amazon 费率 |
| 广告预留 | 例如售价 10%-20% |
| 预估毛利率 | 是否 >= 30% |

如果成本没有数据，UI 要写清楚：利润只是初步估算，不应伪装成确定结论。

### 7. 选品决策

手册要求打分评估市场热度、利润空间、创新度、节日属性，并给 A/B/C 档。

应用应输出：

| 决策项 | 用户语言 |
| --- | --- |
| A 档 | 立即立项，小批量打样/上新 |
| B 档 | 可以排期，但先补图文或供应链确认 |
| C 档 | 暂不考虑，原因明确 |

不要把五个内部评分铺在主卡顶部。普通用户更需要：

- 是否值得做
- 为什么值得做
- 先验证什么
- 下一步做什么

详细分数可以放到“展开依据”里。

## 当前应用的主要问题

### 问题 1：没有研究事务

现在用户点击研究后看到的是一堆候选卡，缺少本次研究的起点、过程和结果边界。

应该改成：

- 研究列表
- 研究详情
- 本次竞品样本
- 本次市场洞察
- 本次候选方案
- 本次转入工坊记录

### 问题 2：原始商品不直观

用户看不到商品图、原标题、关键词、样品来源和详情页状态。

应该把“原始竞品池”放在候选之前，至少展示 top 5；如果是 Etsy SOP，目标应逐步扩展到 top 100 的统计视图。

### 问题 3：AI 输出没有被产品化

现在“差异化”是一段模型输出，而且出现英文。用户需要的是拆解后的运营判断：

| 结构 | 示例 |
| --- | --- |
| 竞品问题 | 低价情侣戒指同质化强，缺少礼品感 |
| 我们怎么改 | 做可刻字双戒套装，附礼盒和纪念卡 |
| 为什么可能卖 | 适合纪念日、订婚、情侣礼物场景 |
| 先验证 | 刻字供应链、退货率、生产时效 |

### 问题 4：缺少利润与合规前置

Etsy 手册把利润和红线放得很前。当前应用如果不展示成本结构、平台费、物流和合规风险，用户无法做立项判断。

尤其首饰类要注意：

- 材质安全
- 过敏风险
- 侵权风险
- 定制商品退货规则
- 纯代发/转售风险
- 包装和发货凭证

### 问题 5：下一步不明确

“转入工坊”对用户不够明确。应该按 SOP 给动作：

- 补成本
- 找供应商
- 生成主图方向
- 生成 Listing 草稿
- 制作打样任务
- 加入上新排期

## 建议的新 UI 信息架构

### 页面一级结构

1. 发起研究
2. 研究记录
3. 研究详情
4. 竞品样本
5. 市场洞察
6. 产品候选
7. 利润测算
8. 决策与下一步

```text
研究：戒指 / 美国 / Etsy + Amazon / 蓝海策略
状态：已完成

1. 本次研究概览

   - 价格

   - 竞争是否过高

4. 候选产品方案
```

## 候选卡新结构

候选卡不应该默认展示内部评分，而应该这样：

```text
推荐方向：可刻字情侣纪念戒指套装
结论：B 档，可进入下月上新池，先确认刻字供应链和礼盒成本。

为什么有机会：
- 竞品里普通情侣戒指有销量，但同质化明显
- 礼品/纪念日场景更适合做情绪价值
- 可通过刻字、礼盒、纪念卡做差异化

原始依据：
- MILACOLATO 情侣戒指，$30，3.9 星，378 reviews
- EIELO 不锈钢戒指套装，$10 左右，review 多但偏普通款

怎么做差异化：
- 竞品问题：普通戒指缺少个性化和礼品感
- 我们方案：免费刻字 + 双戒礼盒 + 纪念卡
- 先验证：刻字成本、生产时效、定制退货规则

利润测算：
- 建议售价：$29-39
- 目标毛利：>=30%
- 待补：采购成本、刻字成本、包装成本、物流成本

下一步：
[找供应商] [生成主图方向] [生成 Listing 草稿] [加入上新排期]
```

## 选品应用应补的数据模型

### research_runs

每次研究一条记录。

| 字段 | 说明 |
| --- | --- |
| id | 研究 ID |
| keyword | 用户输入关键词 |
| market | 目标市场 |
| platforms | 平台列表 |
| strategy | 策略 |
| status | running / completed / failed |
| started_at / finished_at | 时间 |
| summary | 本次研究摘要 |

### research_samples

原始竞品样品。

| 字段 | 说明 |
| --- | --- |
| research_id | 归属研究 |
| platform | 平台 |
| title | 原标题 |
| image_url | 商品图 |
| price | 价格 |
| rating / reviews | 评分和评论 |
| product_url | 商品链接 |
| source_keyword | 来源关键词 |
| detail_status | 是否打开详情 |
| ai_tags | 头部款 / 低价款 / 礼品款 / 可定制款 |

### research_insights

市场洞察。

| 字段 | 说明 |
| --- | --- |
| type | demand / competition / pain_point / visual / season / risk |
| title | 洞察标题 |
| evidence_sample_ids | 依据样品 |
| conclusion | 中文结论 |

### product_candidates

产品立项候选。

应保留当前字段，但新增：

- decision_grade：A / B / C
- target_user
- usage_scene
- competitor_problem
- proposed_change
- why_it_may_sell
- spec_suggestion
- visual_direction
- validation_tasks
- cost_assumptions
- margin_status

## 选品阶段验收标准

一个选品研究不能只看“有没有生成候选”。应该按下面验收：

| 验收项 | 达标标准 |
| --- | --- |
| 研究事务 | 用户能看到一次研究的独立详情和历史记录 |
| 原始样品 | 每次研究至少展示样品图、标题、价格、review、链接 |
| 需求判断 | 有关键词和样品依据，而不是模型空想 |
| 竞品判断 | 能看到价格区间、review 分布、头部/长尾样品 |
| 用户痛点 | 能说明痛点来源；评论未抓取时要明确 |
| 产品定义 | 能输出规格、卖点、目标用户、使用场景 |
| 利润测算 | 至少有售价、成本项、费用项、毛利率状态 |
| 决策评级 | A/B/C 档和下一步动作清晰 |
| 中文可读 | 所有用户可见分析字段必须中文 |
| 可复盘 | 用户能点开样品和链接核实 AI 判断 |

## 对当前开发优先级的建议

第一阶段先别继续扩“AI 生成候选能力”，应该先补研究流程体验：

1. 研究任务化：按 researchId 分组，不混在候选池。
2. 原始竞品池：展示图、标题、价格、评分、review、链接。
3. 研究报告：先输出市场洞察，再输出候选。
4. 候选卡重构：从评分卡改为产品立项卡。
5. 中文输出兜底：生成提示词 + 后处理都要保证中文。
6. 利润测算占位：即使不能自动算，也要让用户知道哪些成本待补。
7. 决策动作：A 档立项、B 档排期、C 档放弃，按钮对应实际动作。

第二阶段再补深能力：

1. EtsyHunt / eRank 或替代关键词来源。
2. 评论抓取和痛点聚类。
3. 竞品图风格聚类。
4. 1688 / Alibaba 供应商候选。
5. 利润测算自动填充。
6. 上新排期和 Listing 草稿联动。

## 对“当前截图”的直接判断

截图里的产物不合格，原因是：

- 没有研究事务，看不出这是哪次研究的完整产物。
- 候选卡没有原始商品图和标题，用户无法判断 AI 看了什么。
- “差异化”是英文段落，且没有拆成竞品问题、改法、销售理由。
- 评分占据主视觉，但用户不理解分数来源。
- “参考竞品”只是几个链接按钮，没有原始样品摘要。
- “转入工坊”缺少上下文，用户不知道转入后做什么。

正确方向不是继续美化这张卡，而是把选品研究改成一个可复盘、可核实、可立项的 SOP 页面。
