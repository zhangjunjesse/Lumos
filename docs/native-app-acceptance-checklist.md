# 内置级应用验收清单

这份清单用于用户 UI 验收和 Claude 开发自查。未通过时不能报告完整完成。

## 1. 应用生成

- 用户能在 `应用 -> 新建` 创建应用草稿。
- 草稿进入应用开发页后，能看到 `项目状态`。
- `项目状态` 能展示 `native-app-spec.json` 的摘要、用户可验收范围、状态覆盖、风险边界和验收清单。
- 修改规格后，状态回到 `待确认`。
- 用户接受当前规格后，安装入口才允许继续。

## 2. 通用页面

- `状态` 页可打开，并显示当前状态、未接入原因和运行数量。
- `状态` 页可点击 `重新运行安装自检`。
- `设置` 页可保存 AI 提示词和风险边界。
- `自动化` 页可查看启用状态、触发规则、最近运行、失败原因，并具备手动运行和同步定时任务入口。
- `通知命令` 页可查看命令模板、风险等级、确认要求、测试结果和失败原因。
- `运行结果` 页可看到运行状态、摘要、失败原因和时间。

## 3. 数据和记录

- `data-schema.json` 包含通用集合。
- 运行动作写入 `run_history`。
- AI 对话写入 `assistant_messages`。
- 通知和命令写入 `app_notifications` / `app_command_runs`。
- 验收进度写入 `acceptance_checks`。

## 4. AI 和写操作

- 使用 AI 时，有可见提示词设置。
- AI 失败时，用户能看到失败原因。
- AI 产生外部写操作前，必须先生成草稿或待确认记录。
- 用户确认前，不发送外部消息，不修改外部系统。

## 5. IM 和自动化

- IM 应用声明 `system.im-notification` 权限。
- 自动化应用声明 `system.schedule` 权限。
- 普通外部微信只读命令只允许 `/app <应用名或ID> status|runs|acceptance|help`。
- 业务命令必须在 `native-app-spec.json.im.lowRiskCommands` 和通知命令页里同时可见。
- 高风险命令必须拒绝或要求回到应用内确认。

## 6. 自检和校验

开发完成前必须通过：

- AppBuilder 工具校验：`validate_app({ nativeGrade: true, files | rootPath })`
- 命令行校验：

```bash
npm run validate:native-app -- <app-dir>
```

安装前，`install_app` 工具和服务端安装接口还会重复执行内置级应用包门禁。安装后必须能看到安装自检结果。安装自检只证明结构、入口和基础数据层可用，不代表外部业务能力已完成。

## 7. 严格汇报

- 只完成规格、页面壳、门禁和结构自检时：`文档完整度=部分完成`，`主链状态=未打通`。
- 用户能完整走 UI 主路径时：`主链状态=已打通`。
- 真实外部账号、IM、定时任务、AI 质量、失败路径和审计都可验收后，才允许说 `完整完成`。
