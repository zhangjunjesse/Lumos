# Etsy 选品 SOP:eRank × AI 实操手册

> 场景:用 eRank + AI 做 Etsy 选品。两个入口——「有想法→验证」和「没想法→发现」,**本手册重点是后者的可重复 SOP**。
>
> 关联文档:
> - `docs/etsy-selection-sop-analysis.md` —— 选品立项流程的产品/功能分析(Lumos 电商模块该怎么做)
> - `docs/etsy-ops-handbook-everstream-export.md` —— 运营总手册全文
> - 本篇是**操作员手册**(怎么用 eRank+AI 实跑),与上面两篇互补,不重复。
>
> 数据快照:2026-05,基于真实 eRank 账号(套餐:GLO 搜索 200/月;Keyword Lists 上限 50)。eRank 配额/功能会变,阈值按当下校准。
>
> 这份文档只回答一件事:如何把 eRank 的趋势词、关键词统计和竞争数据,收敛成“值得继续验证”的关键词机会。它不直接给最终上架结论,也不替代竞品、评论、利润和供应链验证。

---

## 0. 定位

eRank 是 Etsy 的关键词 + 趋势 + 竞争 + SEO 调研工具,**不是上货工具也不是商品库**。它对选品的唯一价值:

> **用「真实搜索需求」对「在售竞争 + 排名难度」,找需求够大但还没被做烂的缺口。**

你不是在 eRank 里"挑一个商品",而是用它的真实数据反推"做什么、用什么词、值不值得进、什么时候进"。

### 0.1 适用范围

- 适用:没想法 → 发现;有想法 → 验证前筛词。
- 不适用:供应链确认、最终定价、详情页文案定稿、上新排期。
- 输出目标:机会表、人工验证结论、待补产品 brief,而不是单纯关键词清单。

### 0.2 阈值原则

- 本文阈值是默认线,不是永久真理。
- 不同类目、季节、客单价会变,先按月校准再固定。
- 任何 A/B/C 结果都要结合趋势和人工验证,不可只看 KD 或竞争。

## 1. 工具地图与指标判读

### 1.1 工具地图

| 工具 | 用途 | 选品里用在哪 |
|---|---|---|
| Keyword Tool | 单词调研 | 有想法时验证核心词 |
| Bulk Keyword Tool | 批量调研 | **接 AI 的验真接口**(烧搜索配额) |
| Keyword Lists + Listing Builder | 收词 + 拼 title/13 tag | 沉淀候选,数据每月自动刷新 |
| Trend Buzz | 正在冒头的词 | **没想法时的种子源(早信号)** |
| Monthly Trends | 类目热词,15 个月历史 | **没想法时的种子源(辨真趋势/季节/昙花)** |
| Category Report | 类目关键词全景 | 没想法时按类目下钻 |
| Rank Checker | 任一词抓前 500 listing | 人工验证:头部能不能打 |
| Top Sellers / Shop Info | 头部店在卖什么 | 人工验证:是否真出单 |
| Competitor Sales(付费) | 指定店每日出单 | 人工验证:确认有钱赚 |
| AI Listing Helper(内置) | eRank 自带 AI 写 listing | **listing 文案用它,喂的是真实数据,比外部 ChatGPT 准** |

### 1.2 指标判读

每个关键词主要列:**月均搜索 | 月均点击 | CTR | Etsy 竞争 | KD | 字符数 | Google 搜索 | 趋势条**。

- **月均搜索** = 需求大小(钱的上限)。
- **Etsy 竞争** = 该词下真实在售 listing 数。**eRank 这列本身绿→红配色,绿=低竞争=好,红=红海;颜色就是红绿灯,不用自己算。**
- **KD(Keyword Difficulty 0–100)** = 综合排名难度。**这是选品最该看的一列。**
- **CTR**:>100% = 一次搜索带来多次点击,买家意图强;**=Unknown / 点击≈0 = 死词**。
- **趋势条**:多月平稳/上升 = 真需求;单峰 = 季节性(需卡月份);持续跌 = 弃。
- **Google 搜索**:站外热度旁证,辅助参考。

### 1.3 选品红绿灯阈值

| 信号 | 🟢 值得做 | 🟡 谨慎 | 🔴 别碰(中小店) |
|---|---|---|---|
| Etsy 竞争(在售数) | < 5,000 | 5千–5万 | > 10万 |
| KD | < 30 | 30–50 | > 60 / =100 |
| 月均搜索 | ≥150 且稳定/升 | 100 左右 | < 100 |
| CTR / 买家意图 | ≥80%(或>100%) | 60–80% | Unknown / ≈0 |
| 趋势 | 多月稳或升 | 单峰季节性 | 持续下滑 |

## 3.「没想法」AI × eRank 选品 SOP(核心)

### 3.1 原则

> 没想法时搜索空间无限,**不能凭空 AI 扩词**(会跑偏 + 烧光配额)。
> 本质:**让市场先开口(eRank 趋势/成交当种子)→ AI 只做整理和打分 → eRank Bulk 验真 → 人工验证能不能打**。
> 一个"机会" = 有需求 ∧ 竞争低 ∧ KD 低 ∧ 买家意图真 ∧ 你能做出来。**五中全中才算,缺一不是机会。**

### 3.2 产物定义:什么叫"一个机会"

SOP 必须收敛到这张表,每行一个机会:

| 机会词 | 对应产品 | 月搜 | 竞争 | KD | CTR/意图 | 趋势 | 为什么是缺口 | 时机 | 验证状态 |
|---|---|---|---|---|---|---|---|---|---|

**判定规则(AI 严格按此筛,不许放水):**

**硬门槛 —— 任一不过直接丢:**
- 月搜 < 100 → 没需求
- CTR = Unknown 或点击 ≈ 0 → 没人买
- Etsy 竞争 > 100,000 → 红海隐形
- KD = 100 → 不能当主攻(只能进标题当副词)

**过门槛后分级:**
- **A 级(主攻)**:月搜 ≥150 且 竞争 <5,000 且 KD <30 且 CTR ≥80%
- **B 级(可做)**:竞争 <50,000 且 KD <50 且 月搜 ≥100 且 CTR ≥80%
- **C 级(只当标题副词)**:需求强但竞争/KD 拉满
- **趋势叠加**:升/多月稳 = 加权;单峰 = 标季节月份;跌 = 降一级

### 3.3 六步 SOP

| 步 | 谁干什么 | 配额 | 产出 |
|---|---|---|---|
| **① 圈猎场** | **AI**:把"你能做/能采购/能 POD 的东西"映射成 3–5 个 Etsy 类目方向(真无约束就跳过,全类目) | 0 | 候选类目 |
| **② 采种子(关键)** | **eRank**:`Trend Buzz` + `Monthly Trends`(看 15 月历史辨真趋势/季节/昙花)+ `Category Report` + `Top Sellers`。**抄原始词,不动脑想** | 0 | 杂乱原始种子 |
| **③ AI 收敛** | **AI**:聚类成"微类目/产品假设",去重、剔红海大词根,每簇补 3–5 长尾词。**总数硬卡 ≤120** | 0 | 待验证清单 CSV |
| **④ eRank 验真** | **eRank**:整段贴进 `Bulk Keyword Tool` → 真实 月搜/竞争/KD/CTR/趋势,导出 | **烧 ≤120** | 真实数据表 |
| **⑤ AI 打分排序** | **AI**:按 3.2 规则筛级排序。**禁止编造表里没有的数字** | 0 | 机会表(A/B/C) |
| **⑥ 人工验证** | **人**:A/B 级用 `Rank Checker`(前 500 看头部能不能打)+ `Top Sellers`/`Competitor Sales`(确认真出单)。AI 替不了 | 0 | 最终机会清单 + 产品 brief |

### 3.4 可复制 AI 提示词

**① 圈猎场:**
> 我能做/能采购的能力:【填,如:vinyl 贴纸、布艺、定制木牌、POD 印花】。映射到 Etsy 上 3–5 个值得调研的类目方向,每个一句话说为什么我能切。只列方向,不要编搜索数据。

**③ 收敛(贴入第②步原始种子):**
> 以下是我从 eRank 趋势/成交抄的原始词:【贴】。① 聚成若干"微类目/产品假设";② 去重;③ 删掉竞争必然爆表的大词根;④ 每簇补 3–5 个具体长尾修饰词(材质/场合/人群/风格)。**总数 ≤120**。输出成一列 CSV,直接能贴进关键词工具。不要给搜索量(你没有真实数据)。

**⑤ 打分排序(贴入第④步 eRank 导出):**
> 这是 eRank 真实导出。硬门槛:月搜<100、CTR=Unknown、竞争>10万、KD=100 任一即淘汰。分级:A=月搜≥150且竞争<5000且KD<30且CTR≥80%;B=竞争<5万且KD<50且月搜≥100且CTR≥80%;C=需求强但竞争/KD高。趋势:升/稳加权,单峰标季节月份,跌降级。**只用表里数字,不许编**。输出机会表:机会词|对应产品|月搜|竞争|KD|CTR|趋势|为什么是缺口(一句)|现在做的时机。按 A→B→C 排。

### 3.5 A/B 级人工验证清单

A/B 级机会进入人工验证时,至少要补一张可回看的验证卡,不能只写“看过了”。

| 项目 | 关注点 | 通过标准 | 否决信号 |
|---|---|---|---|
| 竞品集中度 | 前排是否被少数店铺/品牌垄断 | 多家店铺可见,头部未完全锁死 | 头部长期被少数大店霸占 |
| 价格带 | 竞品售价是否支持你的成本结构 | 目标售价有合理中位带 | 只能打极低价,没有利润空间 |
| 图片差异化 | 主图、场景、包装能否区分 | 视觉入口明显,能做出差异 | 竞品图风格高度一致 |
| 评论痛点 | 买家是否反复抱怨同类问题 | 有稳定高频痛点词 | 评论空白或只有泛夸 |
| 交付风险 | 材质、定制、时效、侵权是否可控 | 风险可解释、可规避 | 易侵权、易退货、难履约 |
| 利润空间 | 毛利能否落在可做区间 | 扣费后仍能 ≥30% | 成本未知或毛利过薄 |

### 3.6 四条护栏

1. **低竞争 ≠ 机会**。先卡需求+买家意图(月搜、CTR),再看竞争。反例见第 4 节 `sheer wedding sign`(竞争仅 62,但月搜<20、CTR Unknown,纯废词)。
2. **配额 200/月**。采种子(②)看免费,只在第④步对收敛后清单花配额;单次 run ≤120 词,别让 AI 扩几百直接喂。
3. **季节性陷阱**。趋势单峰的不是没价值,是必须按那个月份**提前 4–6 周上**,不能当常青品。
4. **清单上限 50**。这套要反复跑 → 固定开一个 `OPP-雷达-月份` 清单专放每轮机会,劣汰旧的;别堆死清单。

### 3.7 节奏

- **每月 1 次完整 run**(②→⑥):产出 5–10 个机会候选,挑 A/B 级 2–3 个上品。
- **每周 5 分钟**:只扫 `Trend Buzz` 有无突冒新词,有就单独加进雷达清单。
- 配额按月重置 → 完整流程放月初跑,月内零散补。

## 4. 真实样例:`EWC lace` 清单判定(证明方法)

数据取自真实账号(2026-05,婚礼标牌 niche,13 词取前 10)。列:月搜 / 竞争 / KD / CTR。

| 关键词 | 月搜 | 竞争 | KD | CTR | 判定 |
|---|---|---|---|---|---|
| lace wedding sign | 363 | 621 | 12 | 61% | 🟢🟢 金矿:有需求、几乎无竞争、极易排 |
| fabric wedding sign | 309 | 3,199 | 51 | 101% | 🟢 缺口:需求 + 低竞争 + 中难度 |
| custom wedding sign | 1,029 | 134,487 | 100 | 125% | 🟡 需求/意图强但竞争+难度拉满 → 仅标题副词 |
| engagement sign | 343 | 39,734 | 100 | 100% | 🟡 竞争尚可但 KD 100,优先级低 |
| wedding backdrop | 203 | 39,318 | 100 | 54% | 🟡 另一品类,需求中、难排 |
| wedding sign | 5,206 | 406,704 | 95 | 109% | 🔴 类目大词红海 → 仅标题锚词 |
| wedding decor | 4,813 | 1,312,302 | 100 | 101% | 🔴 130 万在售,极致红海 |
| romantic wedding | <20 | 126,900 | 100 | Unknown | 🔴 没需求+红海 → 删 |
| vintage wedding sign | 22 | 17,658 | 100 | 118% | 🔴 需求几乎为零 → 删 |
| sheer wedding sign | <20 | 62 | 66 | Unknown | 🔴 **低竞争陷阱典型**:竞争极低但没需求没人点 → 删 |

**结论:** 这张清单把红海大词 + 死词 + 金矿混在一起,看不出主攻。拆开后:**主推楔子 = `lace wedding sign` + `fabric wedding sign`**(低竞争、有需求、易排);`custom/wedding sign` 仅做标题副词蹭量;`romantic/vintage/sheer wedding sign` 删除。时机:`lace wedding sign` 5 月单峰(婚礼季),需提前数周上,非常青。

## 6. 与 Lumos 电商模块的关系

本手册是**人工跑 eRank+AI 的操作 SOP**;`docs/etsy-selection-sop-analysis.md` 分析的是**把这套流程产品化进 Lumos 电商模块**该满足的事务化研究/样本池/利润测算/决策解释要求。两者目标一致(同一套选品标准),一篇给人用、一篇给产品设计用。若后续要把本 SOP 沉淀成 Lumos 工作流,六步结构(②采种子 / ④Bulk验真 / ⑤AI打分 / ⑥人工验证)即天然的步骤边界。

### 6.1 建议的数据产物

如果要把这份 SOP 继续沉淀进 Lumos,建议按下面的最小数据契约存档,这样“看过”才有证据链。

| 阶段 | 产物 | 最少字段 |
|---|---|---|
| 采种子 | `seed_terms` | source_tool, keyword, category, market, note |
| 验真 | `keyword_metrics` | keyword, searches, clicks, ctr, competition, kd, trend, imported_at |
| 收敛 | `opportunity_candidates` | opportunity_keyword, product_guess, grade, seasonality, reason, next_step |
| 人工验证 | `manual_validation_notes` | competitor_ids, price_band, review_notes, image_style, risk_notes |
| 立项 | `product_brief` | target, use_case, value_prop, cost, profit, A/B/C, action |

### 6.2 失败态与重试

任何一次 run 失败后,都应该留下“失败原因 + 可重试动作”,不要只剩一条空状态。

| 失败态 | 典型表现 | 处理方式 |
|---|---|---|
| 未登录 / 登录态失效 | eRank 页面退回未登录页 | 重新打开已登录 AdsPower profile 再跑 |
| 配额不足 | Bulk 无法继续导出 | 暂停本轮,下次配额重置再跑 |
| 导出字段变化 | 列名或位置变了 | 按列名映射,不要按位置硬读 |
| CTR Unknown / 点击≈0 | 只有搜索量,没有点击 | 直接降级或淘汰,不要硬立项 |
| 样本不足 | Top Listings / 商品样本太少 | 标记为“证据不足”,不出 A/B/C 结论 |
| 季节性太强 | 只在单月冲高 | 标记为“季节词”,按提前 4–6 周启动 |
| 规则冲突 | 低竞争但 KD/CTR 很差 | 不按低竞争单项放行,回到人工验证 |

### 6.3 与 Lumos 的映射

如果把这套 SOP 接到 Lumos,建议这样映射:

| SOP 步骤 | Lumos 对应物 | 当前角色 |
|---|---|---|
| 采种子 | 研究任务里的原始样本池 | 采集输入 |
| 验真 | 关键词指标表 | 机会筛选 |
| 收敛 | 机会候选 | AI 归类和打分 |
| 人工验证 | 竞品样本池 + 产品立项卡 | 运营复核 |
| 立项 | A/B/C 决策 + 下一步 | 输出结论 |
